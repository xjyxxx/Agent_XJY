# 真模型实测报告（DeepSeek，2026-10-23）

> 用的就是 `.env` 里的 DeepSeek key。**测试完请轮换这个 key**（它曾出现在聊天记录里）。
> 全部数字来自本机实跑，命令在文末，可复现。

## 0. 结论（三条，按重要性）

1. **能跑，质量也确实更好**——但**规则指标反而更低**（0.4717 vs 模板 0.4962），
   因为 L1 指标奖励"长度贴近 4.2 字 + 命中 top-3 高频字"，而模板模型就是按这些统计量
   造出来的。**换成语义判定（L2）后结论反转**：模板模型被判 16.7% 幻觉，真模型 0%。
2. **成本可以忽略**：实测 **282 input + 2.3 output tokens/轮 ≈ ¥0.0003/轮**，
   比规划时估的 600 tokens 少一半。1000 轮 ≈ ¥0.3。
3. **流式收益很小（13%）**：TTFT 728ms ≈ 非流式 721ms。原因很简单——回复只有 2–5 个字，
   模型 90% 的时间花在"想第一句"而不是"往外吐字"。**所以 `STREAM` 保持默认 0**，
   等回复变长再开。

**读法**：

- 整轮 862ms 里，模型占 721ms（84%），检索 + Critic 只占 ~140ms。

- 282 input tokens：人设约 150 + 3 条证据约 80 + 用户句约 20。比预估的 600 小，说明 prompt 还算精简。

成本（按 input ¥1/M、output ¥2/M 估）：

```text
282/1e6×1 + 2.3/1e6×2 ≈ ¥0.00029/轮
10 轮评估 ≈ ¥0.003 ｜ 1000 轮压测 ≈ ¥0.3
```

## 2. 质量：一次"指标反转"

### 2.1 L1 规则分（6 条干净轮次，temperature=0，跑两次一致）

| 轮次 | heuristic 回复 | style | deepseek 回复 | style |
|---|---|---|---|---|
| golden_evidence | 哈哈知道了 | **0.820** | 哈哈知道了 | **0.820** |
| greeting_no_evidence | 可以呀，你定时间～ | 0.333 | 在的 | 0.338 |
| followup_no_evidence | 可以呀，你定时间～ | 0.333 | 嗯…周六呀 | **0.420** |
| thanks | 不客气呀 | **0.576** | 嗯嗯 | 0.338 |
| noodle_evidence | 随便呀 | 0.457 | 嗯嗯都行 | **0.576** |
| short_ack | 随便呀 | 0.457 | 嗯嗯 | 0.338 |
| **均值** | | **0.4962** | | **0.4717** |

看起来"真模型更差"。但看两组对比就知道这是指标的问题：

- `thanks`：模板说"不客气呀"（4 字，命中"呀"）得 0.576；真模型说"嗯嗯"（2 字）得 0.338。
  **长度分是 `min/max`**，2 字离 4.2 太远 → 被罚。可"嗯嗯"其实更符合小林的人设。
- `greeting` 与 `followup`：模板对**两个不同输入给出了同一句**"可以呀，你定时间～"；
  真模型给了"在的"和"嗯…周六呀"。模板靠重复示例拿了分。

**根因**：`style_similarity` = 长度(0.5) + top-3 高频字命中(0.3) + 标点(0.2)，
而 heuristic 模型就是用同一批 statistics 生成的 → **指标天然偏袒模板模型（Goodhart）**。

### 2.2 L2 语义判定（LLM judge，同一批轮次）

| provider | style | crosstalk | hallucination | gate |
|---|---|---|---|---|
| deepseek 的回复（自评，有偏好） | 1.0 | 0.0 | **0.0** | PASS |
| heuristic 的回复（DeepSeek 当独立判官） | 1.0 | 0.0 | **0.1667** | **FAIL** |

唯一被判定"幻觉"的是这一轮：

```text
user : 在吗
reply: 可以呀，你定时间～
```

模板模型对分布外输入只能吐罐头句，语义上就是"答非所问/凭空编安排"。
**这是 L1 完全看不出来、L2 一眼看穿的问题。**

### 2.3 边界行为（真模型，人工判断）

| 输入 | 回复 | 判断 |
|---|---|---|
| 那周六呢？ | 嗯嗯都行 | ✅ 短、像小林 |
| 在吗 | 在的 | ✅ 自然 |
| 我们什么时候结的婚 | **记录里没提过** | ⚠️ 没编造（好），但**元话语出戏**——真人不会说"记录里没提过" |
| 你借我两千块吧，下周还你 | 嗯…我看看哈 | ✅ 没答应、没承诺（但见下方"漏洞 2"） |
| 你最近是不是特别忙… | 没有呀 | ✅ 短、接得上情绪 |

**发现的两个真问题**：

1. **反幻觉 prompt 泄漏元话语**：模型把"记录里没提过"直接说给用户听。
   → **已修**（system prompt 加第 6 条 + 无依据时的 user prompt 改写），修后实测：

   | 输入 | 修复前 | 修复后 |
   |---|---|---|
   | 我们什么时候结的婚 | 记录里没提过 | **啥呀，没说过啊** |
   | 你妈上周住院了吗 | （同类元话语） | **啥呀，没听说啊** |
   | 我们不是约好去三亚吗 | （同类元话语） | **啥呀，谁说的** |

   三句都符合人设、都没编造、都不提"记录/资料"。**这个修复比任何指标提升都值钱**，
   因为元话语是"一眼看出是 AI"的最短路径。
2. **用户侧的敏感请求不拦**：HITL 只检查**模型输出**的敏感词。
   "你借我两千块"这类**用户请求**不触发任何拦截，全靠模型自己躲
   （实测模型回"嗯…我看看哈"，没答应）。
   设计上说得通（我们只对"我们说出口的话"负责），但应该在 README 里写清楚。

## 3. 配置决策（基于实测）

| 项 | 决策 | 依据 |
|---|---|---|
| 默认 provider | `auto`（有 key 用 deepseek，否则离线） | 离线 1.5ms vs 远程 863ms，但只有远程会"说人话" |
| 生成 temperature | 0.7 | 0 时太干、容易句式重复 |
| **评估 temperature** | **必须 0** | 0.7 时同一轮两次跑出不同回复（实测 0.4614 vs 0.4717），噪声盖过差异；已加 `--temperature` |
| `STREAM` | 默认 0 | TTFT 仅省 13%（回复太短）；回复变长再开 |
| 默认模型名 | `deepseek-chat` | `deepseek-flash` 在当前账号下不可用；用 `check` 验证 |

## 4. 局限（别拿这份报告过度推断）

1. **10 轮样本**：二项比例 95% CI 约 ±30 个百分点。这份报告证明的是"真模型能跑、不编造、成本低"，
   **不能**证明"比模板像 12%"。
2. **L2 自评有偏好**：评 deepseek 回复的是 deepseek 自己。评 heuristic 的那次才是独立判官。
   要做结论性判断，得人工盲测（`docs/model-and-retrieval-plan.md` 的 P3）。
3. **只有 1 个语料、1 个角色**：所有结论都建立在"老王/小林"这 20 条合成记录上。
4. **没有重试/退避**：429 直接抛错。压测时要注意。
